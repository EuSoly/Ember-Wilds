**Goal:** Trocar o avatar do Roblox por um boneco próprio no estilo Starve.io (corpo arredondado, olhos, mãos soltas), com animações por código (parado, andar, golpe, soco), expressões (dano, piscar) e skins de corpo como dados, visível igual para todos os jogadores.

**Architecture:** O personagem do jogo vira um corpo simulado mínimo e invisível (`Humanoid` + `HumanoidRootPart` + `Head` invisível), igual para todos, marcado com a tag `Boneco`. Cada cliente monta, para cada personagem com essa tag, um boneco visual **só local**, com raiz ancorada movida por `workspace:BulkMoveTo` e articulações `Motor6D` animadas por código. O estado que o visual precisa (golpe, item na mão, dano, skin) vem de atributos no personagem. Toda a matemática (curvas de animação, escolha de expressão) fica em módulos puros testados no Lune.

**Tech Stack:** Luau `--!strict`, Rojo 7.7.1, Vide 0.4.1 (não usado aqui), Lune (testes), StyLua, selene, luau-lsp.

**Spec:** `docs/superpowers/specs/2026-10-29-boneco-design.md` (leia inteiro antes da Tarefa 1). Spec geral: `docs/superpowers/specs/2026-10-28-ember-wilds-mvp-design.md`.

## Global Constraints

- Server Authority ligado; o PlayerModule próprio (`vendor/`) já mantém `AutoRotate` desligado e o `FacingSim` gira o `HumanoidRootPart`. Não altere `src/shared/Simulation/*`.
- O boneco visual **nunca** é criado no servidor e nunca é filho do personagem: fica numa pasta local `Workspace.BonecoVisuals` (criada pelo cliente).
- Peças visuais: `Anchored = false` (exceto a raiz), `CanCollide = false`, `CanQuery = false`, `CanTouch = false`, `Massless = true`, `CastShadow = false`, `Material = SmoothPlastic`, superfícies `Smooth`.
- Medidas (studs) e cores do spike aprovado, copiar exatamente para `BonecoConfig` (Tarefa 2): corpo 3,6 × 2 × 3,6, raio do canto 0,9, contorno 0,2 (topo do contorno 0,1 mais baixo), olho Ø 0,95 em x = ±0,8 / z = −0,55, brilho = 32% do olho, mão Ø 1,3 em x = ±1,95 / y = +0,2 / z = −1,45, contorno da mão Ø 1,3 + 0,4 e 0,4 mais baixo. Cores padrão: corpo `#DDF3F8`, contorno `#1F6F7A`, olho `#111111`, brilho `#FFFFFF`.
- Frente do boneco = `−Z` do `HumanoidRootPart` (`LookVector`). Rotação positiva em Y (`CFrame.Angles(0, θ, 0)`) gira a frente para a **esquerda** (−X).
- Atributos (todos no **personagem**): `Using` (bool), `Equipped` (string?), `HurtAt` (number, `workspace:GetServerTimeNow()`), `Cosmetic_<slot>` (string). Tag: `Boneco`.
- Strings de atributo têm no máximo 50 caracteres (limite do Server Authority): IDs de cosmético ≤ 50.
- Textos exibidos: só via `Strings`. Nome do jogador na etiqueta = `Player.DisplayName` (não é texto do jogo, não passa por Strings).

- Produces em `src/shared/BonecoAnim.luau`:
  ```luau
  export type HandPose = { x: number, y: number, z: number, yaw: number } -- deslocamento (studs) em relação à posição de repouso; yaw em radianos em torno do pivô do golpe
  export type Pose = { bodyY: number, left: HandPose, right: HandPose }
  export type Input = { speed: number, using: boolean, hasTool: boolean } -- speed = studs/s no plano
  export type State -- opaco para quem usa: fase do passo, velocidade suavizada, tempo, estado do golpe (ativo, tempo no ciclo, quantos ciclos já começaram)
  BonecoAnim.newState(): State
  BonecoAnim.step(state: State, dt: number, input: Input): Pose
  BonecoAnim.swingCurve(p: number): number -- p em [0,1] → [0,1]; 0 em p=0, 1 em p=SWING_ATTACK_FRACTION, 0 em p=1
  ```
  Regras de `step` (todas lendo `BonecoConfig`):
  - `dt` é limitado a `MAX_DT`.
  - velocidade suavizada: `speedFraction` vai até `clamp(speed / WALK_SPEED_REF, 0, 1)` com suavização exponencial (`SPEED_SMOOTHING`).
  - fase do passo avança `speed * dt * STEP_RATE`.
  - `bodyY = BOB_HEIGHT * |sin(fase)| * speedFraction`.
  - mãos fora do golpe: `left.z = HAND_SWAY * sin(fase) * speedFraction`, `right.z = −left.z`; `y` das duas = `BREATHE_HEIGHT * sin(2π * tempo / BREATHE_PERIOD) * (1 − speedFraction)`.
  - golpe: começa um ciclo quando `using` é `true` e não há ciclo ativo; um ciclo dura `SWING_PERIOD` e **sempre termina** (mesmo se `using` virar `false` no meio); ao terminar, se `using` ainda for `true`, começa outro na hora. No passo em que o ciclo começa, o tempo do ciclo parte de 0 e já soma o `dt` desse passo (depois de `k` passos de `dt`, o tempo é `k * dt`). `p = tempoNoCiclo / SWING_PERIOD`, `c = swingCurve(p)`.
    - com ferramenta (`hasTool`): `right.yaw = rad(SWING_ARC) * c` (repouso yaw 0; o ângulo de repouso de 35° para fora é aplicado pelo visual, não aqui) e `left.z = OTHER_HAND_RECOIL * c` (recua; ignora o balanço do andar).
    - sem ferramenta (soco): a mão do ciclo `n` (contando desde 1) é a direita se `n` for ímpar e a esquerda se for par; essa mão tem `z = −PUNCH_DISTANCE * c`.
  - `swingCurve`: ida com *ease-out* (ex. `1 − (1 − t)^2` com `t = p / A`), volta com *ease-in-out* de 1 a 0 (ex. `0.5 + 0.5 cos(π t)` com `t = (p − A)/(1 − A)`), `A = SWING_ATTACK_FRACTION`. Contínua e dentro de [0,1].
