# Bots que parecem jogadores — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Até 10 bots por servidor (`clamp(20 − jogadores, 0, 10)`) que sobrevivem com as regras do jogo, parecem jogadores (boneco, nome, placar) e só revidam.

**Architecture:** Regras puras novas em `src/shared/Bots/` (quantidade, teto de pontos, provocação, nomes, cérebro e escada de itens), testadas no Lune. Um serviço novo `src/server/Services/BotService/` (pasta com `init.luau` + módulos filhos) roda os bots com estado próprio e mexe no mundo por portas pequenas e **aditivas** nos serviços existentes (nenhum caminho do jogador muda de comportamento). O cliente só ganha: armadura lida do modelo quando não há Player, e bots no placar.

**Tech Stack:** Luau (strict), Rojo, Blink, Lune (testes), Vide (UI), `bash scripts/check.sh`.

**Spec:** `docs/superpowers/specs/2026-11-20-bots-design.md`

## Global Constraints

- `MAX_BOTS = 10`, `TARGET_TOTAL = 20`; alvo = `clamp(min(TARGET_TOTAL, vagas do servidor) − #Players, 0, MAX_BOTS)`.
- Mesmos números do jogador: `SurvivalRules`/`SurvivalConfig`, `CraftRules`/`Defs.Recipes`, `GatherRules`, `MobRules.damageOf`, `ArmorRules`, `CrateRules.killBonus`.
- Escada até pedra: `wood_pickaxe`, `wood_sword`, `campfire`, `workbench`, `stone_pickaxe`, `stone_sword`, `wood_helmet`, `stone_helmet`. Nada de ouro/diamante, parede, porta, espinho, baú, cama.
- Teto de pontos do bot: `BOT_SCORE_CAP` (número único; começar em 3000 e ajustar no teste).
- "Atacou primeiro" = 2 golpes do mesmo jogador em `PROVOKE_WINDOW = 4` s. (Simplificação da spec: "único alvo" cai fora, o golpe não sabe disso sem mudar o `GatherService`; anotar no doc.)
- Bot nunca caça jogador; nunca acerta jogador protegido pelo tutorial nem com `SpawnShieldUntil`.
- Nada do bot é salvo; bot não entra em `StatsService`, `RankService`, `MissionService`, analytics.
- Nomes estilo Roblox, sem repetir no servidor; skins só de cosméticos com `inSpins ~= false`, sem `unreleased`, sem `tags` "limited" (corpo e mochila).
- Tag dos bots: `StatNames.BotTag = "Bot"`; atributos novos no modelo do bot: `BotScore` (number), `BotId` (number negativo, único).
- Atributos só escritos quando mudam; ~1 KB por instância (nada de listas em atributo).
- Comentários e textos em pt-BR, como o resto do código.

## Review Focus

1. Golpe em área do jogador acerta bot e árvore juntos: o bot leva o dano mas **não** revida com 1 golpe só (teste em BotRules.provoked).
2. Jogador entra/sai rápido (10 → 12 → 9): a quantidade converge sem criar e apagar o mesmo bot em loop (histerese: no máximo 1 troca por `POPULATION_EVERY = 5` s; teste em BotRules.populationStep).
3. Bot sem recurso por perto / preso em obstáculo: não fica parado para sempre (cérebro troca de alvo depois de `STUCK_SECONDS = 6` sem progresso; teste em BotBrain).
4. Bot morre com o craft em andamento ou com a fogueira acesa: a caixa leva só o inventário, a fogueira fica até apagar sozinha, nada vaza (verificar no Studio, Task 6).
5. Mob morto pelo bot: a carne vai para o inventário do bot (sem `CrateService` de mob para atacante nil) — verificar no Studio que não aparece caixa órfã nem erro.

### Task 2: Cérebro e escada (puro)

**Files:**
- Create: `src/shared/Bots/BotLadder.luau`
- Create: `src/shared/Bots/BotBrain.luau`
- Test: `tests/botbrain.spec.luau`

**Interfaces:**
- Consumes: `CraftRules.split/canCraft/stationsOf`, `Defs.Recipes`, `Defs.Items`, `SurvivalConfig`/`StatNames.StatusMax`.
- Produces:
  - `BotLadder.STEPS: { string }` = `{ "wood_pickaxe", "wood_sword", "campfire", "workbench", "stone_pickaxe", "stone_sword", "wood_helmet", "stone_helmet" }`
  - `BotLadder.next(owned: { [string]: number }): string?` — primeiro passo cujo item (ou o de cima dele) o bot ainda não tem; `campfire`/`workbench` contam como "tem" se ele tem um posto por perto (ver `Snapshot.nearStation`).
  - `BotLadder.missing(recipeId: string, counts: { [string]: number }): { [string]: number }` (quanto falta de cada ingrediente cru: `wood`, `stone`).
  - `export type Goal = "fight" | "flee" | "warm" | "eat" | "craft" | "place" | "gather" | "hunt" | "wander"`
  - `export type Snapshot = { health: number, hunger: number, cold: number, isNight: boolean, nearFire: boolean, counts: { [string]: number }, nearStation: { [string]: boolean }, provoker: any?, threat: boolean, hasWeapon: boolean, stuckSeconds: number, now: number }`
  - `export type Decision = { goal: Goal, item: string? }` (`item` = receita a craftar/colocar, ou recurso cru a coletar: `"wood"`, `"stone"`, `"berry"`)
  - `BotBrain.decide(s: Snapshot): Decision`

- [ ] **Step 1: Write the failing tests** (`tests/botbrain.spec.luau`):
  - `provoker` presente e vida > 30% → `fight`; vida ≤ 30% → `flee`.
  - `threat` (mob perto) sem arma → `flee`; com arma e vida > 50% → `fight`.
  - noite, `nearFire == false`, tem `wood >= 25` e `stone >= 5` → `place` com `item = "campfire"`; noite sem material → `gather` `wood` (ou `stone`, o que faltar).
  - `cold` abaixo de 40% do máximo de dia → `warm`.
  - `hunger` abaixo de 40% com `berry` no inventário → `eat`; sem comida → `gather` `berry` (ou `hunt` quando `hasWeapon`).
  - sem urgência e escada aponta `wood_pickaxe` com 10 madeira → `craft wood_pickaxe`; com 3 madeira → `gather wood`.
  - receita com estação (`stone_pickaxe`, `workbench`) e `nearStation.workbench == false` mas com material da bancada → `place workbench`.
  - escada completa → `gather` (para pontos) ou `wander`.
  - `stuckSeconds >= 6` com `gather` → troca de alvo: `Decision.item` igual mas `goal = "wander"` uma vez (o servidor sorteia outro alvo).
  - `BotLadder.next` nunca devolve item fora de `STEPS`; com tudo, `nil`.
- [ ] **Step 2:** `lune run tests/run` → falham.
- [ ] **Step 3:** Implementar `decide` como lista de prioridades nesta ordem: fight/flee (provoker) → flee/fight (threat) → warm/place fogueira (noite ou frio baixo) → eat/gather berry/hunt → craft/place estação/gather ingrediente (escada) → wander. Limiares em constantes no topo (`LOW_HEALTH = 0.3`, `LOW_HUNGER = 0.4`, `LOW_COLD = 0.4`, `STUCK_SECONDS = 6`).
- [ ] **Step 4:** `lune run tests/run` → PASS.
- [ ] **Step 5:** Commit `feat(bots): cérebro e escada de itens (puros)`.

### Task 4: BotService (servidor)

**Files:**
- Create: `src/server/Services/BotService/init.luau` — Init/Start; população (`BotRules.target` com `Players.MaxPlayers`, `populationStep` a cada `POPULATION_EVERY`); saída do bot mais longe de todos os jogadores (só some se nenhum jogador está a menos de `HIDE_DISTANCE = 120` studs; senão espera); registra `CharacterService.onNonPlayerHurt`; comandos de Studio (`ServerStorage.DevBots:Invoke(n)` força n / `nil` volta ao automático; `DevBotInfo:Invoke()` → lista nome/objetivo/vida/fome/frio/pontos; `DevKillBot:Invoke(nome?)`).
- Create: `src/server/Services/BotService/Body.luau` — monta o modelo (`CharacterBody.build()`, `HumanoidRootPart` ancorado, `CharacterService.prepare`, tag `BotTag`, `BotId`, nome, `Cosmetic_body`/`Cosmetic_bag` sorteados pela regra das skins, `Armor`, `Equipped`, `Using`, `EatUntil`), move em lote (`Workspace:BulkMoveTo`) na altura do chão.
- Create: `src/server/Services/BotService/Actor.luau` — estado de um bot (inventário via `Inventory`, barras via `SurvivalRules.step`, craft em andamento com `CraftRules.duration`, provocação, objetivo atual) e as ações: andar (`MobMove.step` com círculos de estruturas/recursos/mobs/corpos, sem água/bloqueio do mapa, velocidade `WorldConfig.WALK_SPEED`), golpear (cadência `GatherRules.nextHit`, alcance `HIT_REACH + HeldItem.reach`, `Using` liga no golpe), coletar (`GatherRules.yield` + `ResourceService.take` + `GatherService.resourceFx` + pontos `gather.points` com teto), craftar (tempo da receita, item na mão "em uso"), colocar (`StructureService.placeForBot`), comer (`EatRules`/`SurvivalService`-equivalente sobre as barras do bot + `EatUntil`), lutar (contra jogador: `CharacterService.hurt(character, MobRules.damageOf(arma, armadura), "death.cause.player", "player", nil, nomeDoBot)`, só no provocador, nunca em protegido/escudado; contra mob: `MobService.damage(mob, dano, nil)` e, se o mob morreu, `def.loot` vai para o inventário).
- Modify: `docs/superpowers/specs/2026-11-20-bots-design.md` — anotar a simplificação do "único alvo".

**Comportamento que precisa estar certo:**
- Dano no bot (ouvinte do `onNonPlayerHurt`): defesa da armadura do bot (`ArmorRules.reduce`), vida baixa → morte; golpe de jogador alimenta `BotRules.recordHit`.
- Morte: `CrateService.spawn(x, z, slots do inventário, modelo de caixa padrão, lifetime da caixa de morte do jogador)`; matador Player ganha `ScoreService.add(killer, CrateRules.killBonus(BotScore))`; nada de Stats/Rank/Missão; estruturas do bot ficam (fogueira apaga sozinha; bancada some com `removeOwned` quando o bot sai do jogo, não quando morre); vaga esfria `RESPAWN_DELAY = 20` s.
- Barras a cada `SurvivalConfig.TICK` com `fireAround` equivalente (fontes de calor com `StatNames.HeatSourceTag`, como o SurvivalService); cérebro a cada `THINK_EVERY = 0.5` s, ou `FAR_THINK_EVERY = 2` s sem jogador a `FAR_RADIUS = 150` studs.
- Pontos: `BotScore` sobe com coleta/craft/mob como o jogador (`gather.points`), sempre por `BotRules.addScore`.
