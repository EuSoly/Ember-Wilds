# Tutorial da primeira partida — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tutorial obrigatório de 6 etapas na primeira partida, com proteção de até 10 minutos, rastro até o alvo, destaques na interface, selo no nome, 2 giros normais de prêmio e pop-up da roleta no menu.

**Architecture:** As etapas são dados (`shared/Tutorial/TutorialSteps`) e as regras são puras e testadas (`shared/Tutorial/TutorialRules`, `shared/Tutorial/TrailRules`). O servidor (`TutorialService`) decide começo, avanço, proteção, prêmio e o que fica salvo no perfil, e publica tudo em atributos do `Player`. O cliente (`client/TutorialState`) lê esses atributos e desenha o quadrinho, o rastro, os destaques, o selo e o pop-up.

**Tech Stack:** Luau `--!strict`, Vide (UI), Blink (rede: `net/game.blink`), ProfileStore (`DataService`), testes no Lune (`lune run tests/run`), verificação `bash scripts/check.sh`.

**Spec:** `docs/superpowers/specs/2026-11-10-tutorial-design.md`

## Global Constraints

- Tutorial obrigatório, sem botão de pular.
- 6 etapas, nesta ordem: 10 `wood` → 1 `wood_pickaxe` → 5 `berry` → ver a ficha da `campfire` no livro → colocar uma `campfire` → entrar na água do mapa.
- Proteção: termina ao completar a etapa 6 ou 600 s depois de nascer, o que vier primeiro. Depois dos 600 s, o tutorial continua e ainda dá o prêmio.
- Prêmio: 2 giros normais (`Spins.normal`), dados uma vez só, pelo servidor, via `ShopService.give(player, { kind = "spins", spin = "normal", count = 2 }, "tutorial")`.
- O progresso não fica salvo: cada vida nova com o tutorial incompleto começa da etapa 1. No perfil vão só `Tutorial.Done` e `Tutorial.SpinPopup`.
- Todo texto vai em `src/shared/Strings/ptBR.luau`, usando `Strings.get` ou `Strings.format(key, vars)` com `{nome}`.
- Atributos que o cliente lê ficam no **Player**, não no personagem: o `AttributeChanged` não dispara no personagem previsto.
- Cada task termina com `bash scripts/check.sh` verde (é preciso `export PATH="$HOME/.rokit/bin:$PATH"`) e com `"$(cat graphify-out/.graphify_python)" -m graphify update .`.
- Se o Rojo cair depois de StyLua reescrever arquivos, reinicie com `rojo serve default.project.json`.

## Review Focus

1. **Jogador sai do jogo ou morre (depois dos 10 min) no meio do tutorial.** A próxima vida recomeça da etapa 1, sem prêmio duplicado e sem estado velho: teste `restart_from_zero` na Task 1, e a checagem no Studio na Task 7.
2. **Já tem itens no inventário ao chegar numa etapa** (ex. 10 madeiras antes da etapa 1 terminar, ou uma picareta pega de uma caixa). A etapa completa logo e avança uma por vez, sem pular etapas no mesmo tick: teste `advances_one_step_per_check` na Task 1.
3. **A árvore ou o arbusto mais perto está esgotado (`Amount = 0`).** O rastro vai para o próximo com `Amount > 0`: teste no Studio na Task 4.
4. **A proteção acaba (600 s) com a fome ou a sede zerada.** O dano normal volta, e o tutorial continua mostrando o quadrinho: teste `protection_expires` na Task 1, e a checagem no Studio na Task 2.
5. **Jogador protegido bate num jogador, num bicho, numa construção alheia ou numa caixa de loot.** Nada acontece. Num recurso, a coleta é normal: checagem no Studio na Task 2.

**Interfaces:**
- Produces:
  - `TutorialSteps.LIST: { Step }`, com 6 itens.
  - `type Goal = { kind: "have", item: string, count: number } | { kind: "view", item: string } | { kind: "place", item: string } | { kind: "drink" }`
  - `type Step = { id: string, textKey: string, goal: Goal, sources: { [string]: string }?, recipe: string? }`. Em `sources`, a chave é o item e o valor é o `ResourceId` de onde ele sai.
  - Os passos, em ordem:
    - `wood`: goal have wood 10, sources `{ wood = "tree" }`.
    - `pickaxe`: goal have wood_pickaxe 1, recipe `"wood_pickaxe"`.
    - `berries`: goal have berry 5, sources `{ berry = "berry_bush" }`.
    - `book`: goal view campfire.
    - `campfire`: goal place campfire, sources `{ wood = "tree", stone = "rock" }`, recipe `"campfire"`.
    - `water`: goal drink.
  - O `textKey` de cada etapa é `"tutorial.step.<id>"`.
  - `TutorialRules.PROTECTION_SECONDS = 600`, `TutorialRules.DRINK_SECONDS = 1.5`, `TutorialRules.REWARD_SPINS = 2`.
  - `type Facts = { counts: { [string]: number }, placed: { [string]: boolean }, viewed: { [string]: boolean }, wetSeconds: number }`
  - `TutorialRules.isDone(step: Step, facts: Facts): boolean`
  - `TutorialRules.progress(step: Step, facts: Facts): (number, number)`. Devolve "tem e precisa": para "have" é `(min(tem, meta), meta)`; para os outros, `(0 ou 1, 1)`.
  - `TutorialRules.advance(index: number, facts: Facts): number`. Devolve `index + 1` se a etapa `index` está feita, senão `index`. Avança no máximo uma etapa por chamada; `#LIST + 1` quer dizer completo.
  - `TutorialRules.needs(step: Step, counts): { { item: string, count: number } }`. Para "have", devolve a meta. Para "place", devolve os ingredientes da receita `Defs.Recipes[step.recipe]`, ou vazio se já tem o item. Para os outros, vazio.
  - `TutorialRules.trailTarget(step: Step, counts): string?`. Para "drink", devolve `"water"`. Senão, devolve `sources[item]` do primeiro item de `needs` que está faltando, ou `nil`.
  - `TutorialRules.canCraft(recipeId: string, counts): boolean`. É true quando todos os ingredientes estão no inventário.
  - `TutorialRules.protected(startedAt: number, now: number): boolean`. É `now - startedAt < PROTECTION_SECONDS`.
