**Goal:** Salvar por jogador tudo o que sobrevive à morte — Golden Ember, estatísticas (inclusive por tipo), cosméticos e configurações — com ProfileStore, versão de schema e migrações, convertendo os pontos de cada vida em moeda com tetos anti-farm.

**Architecture:** As regras ficam em módulos puros em `src/shared/Data/` (testados no Lune): conversão e tetos da moeda, aplicação de estatísticas, validação de configurações, migrações e o template do perfil. No servidor, o `DataService` abre/fecha a sessão do ProfileStore de cada jogador e avisa quando o perfil carregou e quando vai fechar; serviços pequenos usam isso: `CurrencyService` (saldo), `StatsService` (estatísticas + aviso de mudança para conquistas futuras), `LifeService` (fim de vida: pontos → moeda e estatísticas, uma vez por vida), `SettingsService` (configurações via Blink) e o `CosmeticService` existente (passa a ler/gravar no perfil). O cliente só lê atributos do Player.

**Tech Stack:** Luau `--!strict`, Rojo 7.7.1, Wally (ProfileStore `lm-loleris/profilestore@1.0.3`, realm server), Blink 0.18.9, Lune.

**Spec:** `docs/superpowers/specs/2026-10-29-f4-dados-design.md` (leia inteiro antes da Tarefa 1). Spec geral: `docs/superpowers/specs/2026-10-28-ember-wilds-mvp-design.md` §7. Pesquisa: `docs/research/02-dados-monetizacao.md`.

## Global Constraints

- Perfil: chave `Player_{UserId}`; store `PlayerData`, e no Studio `Dev_PlayerData` (`RunService:IsStudio()`). `profile:AddUserId(userId)` em todo perfil (GDPR).
- Schema v1: `SchemaVersion = 1`, `Currency = { Balance = 0, HourWindowStart = 0, HourEarned = 0 }`, `Cosmetics = { Owned = {}, Equipped = {} }`, `Stats = {}`, `Settings = { ...padrões de Defs.Settings }`, `PurchaseIdCache = {}`.
- Golden Ember: `floor(pontos / 1000)`, **máx. 500 por vida**, **máx. 300 por hora** (janela fixa: começa no 1º ganho, zera 3600 s depois, relógio `os.time()`). O teto por hora só vale para ganhos do jogo (`earnFromGameplay`), não para `grant` (compras/dev). Números em `DataConfig`.
- Estatísticas iniciais (id, kind): `players_killed` counter · `mobs_killed` keyed(mob) · `resources_gathered` keyed(item) · `items_crafted` keyed(item) · `deaths` counter · `score_total` counter · `score_best` max · `days_best` max · `playtime_seconds` counter.
- Chaves de estatística keyed: `^[a-z0-9_]+$`, até 32 caracteres.
- Configurações iniciais: `music_volume`, `ambient_volume`, `effects_volume` (number 0–1, padrão 0.8) · `quality` (choice `auto|low|medium|high`, padrão `auto`) · `ui_scale` (number 0.8–1.25, padrão 1) · `left_handed` (boolean, padrão false).
- Fim de vida: **uma vez por vida**; vida nova começa no próximo `CharacterAdded`; `days_best = floor(segundosVivo / 480)`.
- Atributos novos no Player: `Currency` (number), `Setting_<id>` (valor da configuração).
- Textos: `currency.name` = "Golden Ember"; `data.loadFailed` = "Não foi possível carregar seus dados. Tente entrar de novo."; `data.sessionTaken` = "Seus dados foram abertos em outro servidor."; `data.newerVersion` = "O jogo foi atualizado. Entre de novo para continuar."; `data.devReset` = "Perfil de desenvolvimento apagado. Entre de novo."; `stat.<id>` e `setting.<id>` para cada estatística/configuração (textos curtos em pt-BR escolhidos por você).

## Review Focus

1. **Jogador sai enquanto o perfil ainda está carregando** → a sessão é encerrada assim que abrir (ou cancelada), sem perfil "pendurado" e sem erro. (Tarefa 3: `Cancel` + checagem pós-carregamento.)
2. **Fim de vida chamado duas vezes** (morreu e saiu; `PlayerRemoving` + desligamento do servidor) → moeda e estatísticas contam uma vez só. (Tarefa 4: teste do guarda de vida no `LifeRules`.)
3. **Perfil salvo por uma versão mais nova do jogo** (`SchemaVersion` maior que a atual) → o jogador é expulso com `data.newerVersion` e os dados **não** são alterados. (Tarefa 2: teste de `Migrations.run`; Tarefa 3: uso.)
4. **Configuração inválida vinda do cliente** (id inexistente, NaN, fora da faixa, tipo trocado, opção inexistente) → ignorada, valor salvo não muda. (Tarefa 2: testes de `SettingsRules`.)
5. **Pontos estranhos no fim da vida** (negativo, NaN, não inteiro, enorme) → nunca gera moeda negativa/NaN; respeita os tetos. (Tarefa 2: testes de `CurrencyRules`.)

### Tarefa 2: Regras puras de dados (moeda, estatísticas, configurações, migrações, template)

**Files:**

- Test: `tests/currency.spec.luau`, `tests/stats.spec.luau`, `tests/settings.spec.luau`, `tests/life.spec.luau`, `tests/migrations.spec.luau`

**Interfaces** (todos puros, sem APIs do Roblox):
- `DataConfig` (tabela congelada): `STORE_NAME = "PlayerData"`, `DEV_STORE_PREFIX = "Dev_"`, `KEY_PREFIX = "Player_"`, `SCHEMA_VERSION = 1`, `POINTS_PER_CURRENCY = 1000`, `MAX_CURRENCY_PER_LIFE = 500`, `MAX_CURRENCY_PER_HOUR = 300`, `HOUR_SECONDS = 3600`, `DAY_CYCLE_SECONDS = 480`, `STAT_KEY_MAX_LENGTH = 32`.
- `CurrencyRules`:
  ```luau
  export type CurrencyData = { Balance: number, HourWindowStart: number, HourEarned: number }
  CurrencyRules.pointsToCurrency(points: number): number -- floor(points / 1000), no máx. MAX_CURRENCY_PER_LIFE; NaN/negativo/infinito → 0
  CurrencyRules.earn(data: CurrencyData, amount: number, now: number): number -- aplica o teto por hora; soma no saldo; devolve quanto foi concedido
  CurrencyRules.grant(data: CurrencyData, amount: number): boolean -- sem tetos (compras/dev); amount inteiro >= 0
  CurrencyRules.spend(data: CurrencyData, amount: number): boolean -- false se amount inválido ou saldo insuficiente (saldo não muda)
  ```
  Janela por hora: se `HourWindowStart == 0` ou `now - HourWindowStart >= HOUR_SECONDS`, a janela recomeça em `now` com `HourEarned = 0`. Concedido = `min(amount, MAX_CURRENCY_PER_HOUR - HourEarned)` (nunca negativo). `amount` inválido (NaN, negativo, não inteiro) → 0.
- `StatsRules`:
  ```luau
  StatsRules.isValidKey(key: string): boolean
  StatsRules.add(stats: { [string]: any }, def: StatDef, amount: number, key: string?): number? -- counter/keyed; devolve o novo valor (o da chave, no keyed) ou nil se inválido
  StatsRules.record(stats: { [string]: any }, def: StatDef, value: number): (number?, boolean) -- só "max"; devolve (valor guardado, mudou?) ou (nil, false) se inválido
  StatsRules.get(stats: { [string]: any }, def: StatDef, key: string?): number -- 0 se não existe
  ```
  Regras: `amount` finito e `> 0` (pode ser fracionário, ex. segundos); `value` finito e `>= 0`; counter/max **não** aceitam `key`; keyed **exige** key válida; a tabela de um keyed é criada na primeira soma (é isso que dispensa migração para estatística nova).
- `SettingsRules`:
  ```luau
  SettingsRules.validate(def: SettingDef, value: any): (boolean, SettingValue?) -- válido? (sem corrigir: fora da faixa é inválido)
  SettingsRules.defaults(defs: { [string]: SettingDef }): { [string]: SettingValue }
  ```
- `LifeRules` (guarda "uma vez por vida" e a conta de dias):
  ```luau
  export type Life = { active: boolean, startedAt: number }
  LifeRules.start(now: number): Life
  LifeRules.finish(life: Life?, now: number): number? -- se a vida está ativa: marca inativa e devolve os segundos vividos; senão nil
  LifeRules.daysSurvived(seconds: number): number -- floor(seconds / DAY_CYCLE_SECONDS), mínimo 0
  ```
- `Migrations`:
  ```luau
  export type Step = (data: { [string]: any }) -> ()
  Migrations.STEPS: { [number]: Step } -- STEPS[n] leva da versão n para n+1; vazio na v1
  Migrations.run(data: { [string]: any }, steps: { [number]: Step }, target: number): (boolean, string?)
  ```
  `data.SchemaVersion` nil → trata como `target` (perfil novo). Igual ao target → ok. Menor → aplica `steps[v]` em ordem, atualizando `SchemaVersion` a cada passo; passo faltando → `(false, "sem migração de vN")` e **não** muda nada (aplique numa cópia e só copie de volta no fim). Maior → `(false, "newer")` sem mudar nada.
- `ProfileTemplate.build(defs: Types.DefsTables): { [string]: any }` — o template da seção Global Constraints (`Settings` = `SettingsRules.defaults(defs.Settings)`), tabela nova a cada chamada.

### Tarefa 4: Moeda, estatísticas e fim de vida

**Files:**
- Create: `src/server/Services/CurrencyService.luau`, `src/server/Services/StatsService.luau`, `src/server/Services/LifeService.luau`

**Interfaces:**
- Consumes: `DataService` (T3), `CurrencyRules`, `StatsRules`, `LifeRules`, `DataConfig` (T2), `Defs.Stats`, `StatNames`.
- `CurrencyService`:
  ```luau
  CurrencyService.balance(player: Player): number -- 0 sem perfil
  CurrencyService.earnFromGameplay(player: Player, amount: number, reason: string): number -- com teto por hora; devolve o concedido
  CurrencyService.grant(player: Player, amount: number, reason: string): boolean -- sem tetos (compras/dev)
  CurrencyService.spend(player: Player, amount: number, reason: string): boolean
  ```
  Toda mudança atualiza o atributo `StatNames.Currency` do Player; ao carregar o perfil, publica o saldo. `reason` vai num comentário/log de Studio (não precisa salvar). Sem perfil carregado: não faz nada (devolve 0/false).
- `StatsService`:
  ```luau
  StatsService.add(player: Player, statId: string, amount: number, key: string?): ()
  StatsService.record(player: Player, statId: string, value: number): ()
  StatsService.get(player: Player, statId: string, key: string?): number
  StatsService.onChanged(listener: (player: Player, statId: string, key: string?, value: number) -> ())
  ```
  Estatística desconhecida ou valor inválido → `warn` e ignora. `onChanged` só dispara quando o valor muda de fato (comentário: "é aqui que conquistas e maestria vão se ligar").
  **Tempo de jogo:** guarda por jogador o instante da última soma (`os.clock()`) ao carregar o perfil; no `DataService.onBeforeSave` e no `onUnloading`, soma `playtime_seconds` com o tempo desde a última soma e atualiza a marca.
- `LifeService`:
  ```luau
  LifeService.endLife(player: Player): () -- fim de vida (as fases G chamam ao morrer)
  ```
  - No `CharacterAdded` de cada jogador: se não há vida ativa, começa uma (`LifeRules.start(os.clock())`).
  - `endLife`: `LifeRules.finish` → nil = já terminada, sai. Senão: `score = Player:GetAttribute(StatNames.Score)` (número válido ou 0); `CurrencyService.earnFromGameplay(player, CurrencyRules.pointsToCurrency(score), "life_end")`; se `score > 0`, `StatsService.add(player, "score_total", score)`; `StatsService.record(player, "score_best", score)`; `StatsService.record(player, "days_best", LifeRules.daysSurvived(segundos))`; `StatsService.add(player, "deaths", 1)`; `Player:SetAttribute(StatNames.Score, 0)`; `DataService.save(player)`.
  - `DataService.onUnloading` → `endLife(player)` (sair do jogo e desligar o servidor contam como morte).
  - O `LifeService` e o `StatsService` (tempo de jogo) rodam no mesmo `onUnloading`, antes do último save; a ordem entre eles não importa (mexem em campos diferentes).
