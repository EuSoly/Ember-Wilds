# F2 HUD — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HUD mobile-first do layout da identidade visual (anéis de status, hotbar, pontos, relógio, minimapa, notificações, botão de mochila) feito em Vide, alimentado por atributos com dados falsos, e o joystick direito do celular que mira e segura a ação de "bater".

**Architecture:** Contratos de dados em `src/shared` (nomes de atributos, matemática do ciclo de dia, do anel e do joystick — testados no Lune). O servidor publica os atributos (dados falsos no Studio por um serviço de desenvolvimento) e cria as InputActions. O cliente monta uma árvore Vide num `ScreenGui` e lê só atributos e InputActions — nunca o Workspace.

**Tech Stack:** Luau `--!strict`, Vide 0.4.1 (Wally), Input Action System, Rojo 7.7.1, Lune.

**Spec:** `docs/superpowers/specs/2026-10-28-ember-wilds-mvp-design.md` (seções 5, 8 e 10 — inclui a decisão de dois joysticks de 29/10/2026)

## Global Constraints

- Tudo do F0/F1 continua valendo: `--!strict`, identificadores em inglês, comentários em pt-BR, textos só via `Strings`, cores só via `Theme`/`Palette`, Init/Start, Server Authority (input da simulação vem de InputAction).
- UI: tudo em Scale com `UIAspectRatioConstraint`; `TextScaled` + `UITextSizeConstraint` (mín. 12); botões de toque ≥ 44 px e nada a menos de 12 px da borda; painéis `Theme.ui.panel` a 85% (`BackgroundTransparency = Theme.panelTransparency`), `UICorner` 12, `UIStroke` 1 px `Theme.ui.border`; slot 40–56 px, `UICorner` 8, selecionado com borda `Theme.ui.action` de 2 px; texto branco quente com `UIStroke` 1,5–2 px `Theme.ui.panel`.
- `ScreenGui` do HUD com `ScreenInsets = Enum.ScreenInsets.CoreUISafeInsets`, `ResetOnSpawn = false`, `IgnoreGuiInset = false`.
- O HUD não lê o Workspace (exceto a posição do próprio personagem para o minimapa).
- Fontes: `Theme.font.number` para números, `Theme.font.label` para rótulos.
- Ciclo: dia 240 s + noite 240 s; aviso 30 s antes da noite.
- Commit por tarefa, mensagem em pt-BR, sem push. Branch `f2-hud`.
- Verificação: `bash scripts/check.sh` (Git Bash) e, para UI, Play no Studio pelo MCP `Roblox_Studio` (Output sem erros + inspeção da árvore do `PlayerGui` + `screen_capture` quando funcionar em Play).
- Após mudar código: `& (Get-Content graphify-out\.graphify_python) -m graphify update .` (PowerShell).

## Review Focus

1. **Atributo ainda não existe quando o HUD monta** (cliente entra antes do servidor setar) — o anel/rótulo mostra um valor padrão (cheio / 0 pontos), sem erro, e atualiza quando o atributo chega. (Task 4: `AttributeSource` com padrão; teste no Studio.)
2. **Troca de dispositivo no meio da sessão** — joystick direito e botão de mochila aparecem só com `PreferredInput == Touch`; ao trocar, somem/aparecem sem recriar o HUD. (Task 8.)
3. **Joystick solto fora da área / dedo que sai da tela / segundo dedo** — o joystick acompanha só o toque que começou nele; ao soltar em qualquer lugar, `Use = false` e mira zerada. (Task 8: rastrear o `InputObject` do toque inicial.)
4. **Respawn** — o HUD não é recriado (`ResetOnSpawn = false`) e o minimapa passa a seguir o personagem novo. (Task 6.)
5. **Valores fora da faixa** (atributo de status < 0 ou > 100, NaN) — o anel trava em [0, 1] e não quebra. (Task 3: `RingMath.filledCount` com clamp; teste.)

### Task 3: Matemática do anel e do joystick (shared)

**Files:**
- Create: `src/shared/UIMath.luau`, `tests/uimath.spec.luau`

**Interfaces:**
- Produces:
  - `UIMath.filledCount(value: number, max: number, segments: number): number` — `round(clamp(value / max, 0, 1) * segments)`; NaN → 0.
  - `UIMath.segmentAngle(index: number, segments: number): number` — radianos, segmento 1 no topo (12 h) e seguindo no sentido horário: `-math.pi / 2 + (index - 1) * 2π / segments`.
  - `UIMath.stick(dx: number, dy: number, radius: number, deadzone: number): (number, number, boolean)` — direção unitária `(x, y)` em coordenadas de tela (x para a direita, y para baixo) e `active`; `active = false` e `(0, 0)` se `sqrt(dx²+dy²) < deadzone`. Como a câmera não gira, `(x, y)` de tela é direto o `(x, z)` do mundo usado na `Aim`.
- [ ] **Step 1: Write the failing tests:** `filledCount(50,100,20) == 10`; `filledCount(150,100,20) == 20`; `filledCount(-10,100,20) == 0`; `filledCount(0/0,100,20) == 0`; `filledCount(34,100,20) == 7`; `segmentAngle(1,20) ≈ -π/2`; `segmentAngle(6,20) ≈ 0`; `stick(30, 0, 60, 10)` → `(1, 0, true)`; `stick(0, -30, 60, 10)` → `(0, -1, true)`; `stick(3, 4, 60, 10)` → `(0, 0, false)`; `stick(120, 0, 60, 10)` → `(1, 0, true)`.
